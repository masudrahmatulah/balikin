# Strategi Peluncuran, Pemasaran Berantai, & Sistem Klaim "Balikin"

**Target Pasar Awal:** Mahasiswa (Massa Kampus Regional - Fokus Satu Pulau)
**Metode Utama:** Social Proof (Testimoni) + Viral Loop (Referral Berantai Berinsentif) + Anti-Fraud System + Automated Claim Dashboard

## 📌 Ringkasan Konsep

Strategi ini menggabungkan dua kekuatan utama dalam pertumbuhan startup:
- **Bukti Sosial (Social Proof)** untuk membangun kepercayaan di awal
- **Siklus Viral (Viral Loop)** agar aplikasi memasarkan dirinya sendiri dari mulut ke mulut secara otomatis

Guna menjamin kesuksesan operasional, strategi ini difokuskan pada area satu pulau untuk:
- Efisiensi logistik super cepat (pengiriman 1 hari)
- Pengaman sistem dari kecurangan
- Manajemen klaim hadiah yang otomatis di aplikasi

## 🚀 Fase 1: Kampanye 50 Gantungan Kunci Pertama (Mencari Testimoni)

Tujuan utama fase ini adalah mengumpulkan aset visual dan ulasan positif nyata dari pengguna aktif pertama untuk dipajang di landing page.

### 1. Distribusi Terarah & Skema Anti-Macet (Dead Hardware Prevention)

**Target:** 50 mahasiswa lokal yang memiliki mobilitas tinggi, aktif berorganisasi, atau sering membawa barang berharga ke kampus/kafe.

**Metode:** Distribusi gratis dengan skema registrasi slot terbatas (scarcity marketing).

**Aturan Aktivasi Ketat:**
- Penerima wajib melakukan aktivasi akun dan QR Code dalam waktu 2 × 24 jam setelah menerima barang
- Jika tidak diaktifkan, hak akses premium gratis selama 1 tahun akan dicabut
- Hak akan dialihkan kepada mahasiswa lain dalam daftar tunggu (waiting list)
- Langkah ini memastikan barang tidak hanya disimpan di laci, melainkan langsung digunakan

### 2. Alur Pengumpulan Testimoni (Dual-Form System)

Formulir ulasan dibagi menjadi dua bagian untuk memisahkan fungsi pemasaran dan evaluasi:

#### Form A: "Form Gembira" (Aset Marketing)
- **Isi:** Pertanyaan tentang kemudahan, kenyamanan, dan rasa aman setelah menggunakan Balikin
- **Aset Tambahan:** Kolom unggah foto selfie atau estetik pengguna sedang memegang barang kesayangnya yang telah ditempeli gantungan kunci Balikin
- **Identitas:** Kolom Nama, Kampus, dan Jurusan (Contoh: Rian - Teknik Informatika, Kampus X) untuk meningkatkan kredibilitas regional di landing page

#### Form B: "Kritik & Saran" (Evaluasi Internal - Opsional)
- **Isi:** Kolom khusus untuk menceritakan kendala, bug, atau fitur yang dirasa kurang
- **Fungsi:** Bahan perbaikan produk tanpa merusak ulasan positif yang akan dipajang ke publik

## 🔄 Fase 2: Strategi Harga & Viral Loop (Referral Berantai)

Setelah mahasiswa di Fase 1 mengisi ulasan mereka, sistem akan secara otomatis mengaktifkan fitur referral agar mereka terdorong untuk mempromosikannya ke lingkaran pertemanan mereka.

### 1. Struktur Harga Psikologis

| Jenis | Harga |
|------|-------|
| **Harga Coret (Anchor Price)** | Rp54.000 |
| **Harga Diskon (Menggunakan Voucher)** | Rp44.000 |
| **Branding Diskon** | "Hemat Rp10.000" (≈ 18,5%) |

**Alasan:** Nominal rupiah terlihat lebih bernilai nyata bagi mahasiswa dibanding persentase.

### 2. Mekanisme Referral Berantai

**Pemicu (Trigger):** Begitu ulasan Fase 1 dikirim, pengguna mendapatkan kode voucher unik yang dipersonalisasi dengan namanya (Contoh: RIANBALIKIN).

**Batas Waktu (Urgency):** Voucher hanya berlaku selama 15 hari sejak diterbitkan. Karena pengiriman di satu pulau hanya memakan waktu 1 hari, masa berlaku ini sangat logis dan menuntut pergerakan cepat secara organik.

**Insentif Pembagi Voucher:** Jika kode vouchernya digunakan oleh 10 orang baru untuk membeli Balikin, pemilik voucher berhak mengklaim hadiah saldo e-wallet (GoPay/OVO) sebesar Rp50.000.

**Siklus Berantai:** Setiap pembeli baru yang membeli menggunakan voucher tersebut, setelah melakukan pembayaran, akan otomatis mendapatkan kode vouchernya sendiri (masa aktif 15 hari) untuk dibagikan kembali ke teman-teman mereka. Siklus ini akan terus berputar secara organik.

## 💸 Analisis Keuangan & Optimasi Transaksi (Simulasi per 10 Penjualan)

Menggunakan asumsi Biaya Pokok Produksi (HPP) gantungan kunci fisik dan operasional sebesar **Rp15.000 per unit**.

### Perhitungan (10 Penjualan)

| Item | Nominal |
|------|---------|
| **Pendapatan Kotor** (10 × Rp44.000) | Rp440.000 |
| **Biaya Produksi** (10 × Rp15.000) | Rp150.000 |
| **Hadiah E-Wallet Referral** | Rp50.000 |
| **Total Pengeluaran** | Rp200.000 |
| **Keuntungan Bersih (Net Profit)** | **Rp240.000** |
| **Per Unit** | **Rp24.000** |

### Catatan Optimasi Biaya

- **Pembayaran:** Prioritaskan QRIS untuk menekan biaya payment gateway hingga ≈ 0,7% per transaksi
- **Hadiah Referral:** Dapat diubah menjadi kemitraan lokal (seperti voucher kedai kopi lokal bernilai Rp50.000 dengan harga korporat khusus)

## 🔒 Aturan Keamanan & Pencegahan Kecurangan (Anti-Fraud)

Untuk menghindari manipulasi sistem oleh pengguna cerdik, sistem wajib menerapkan aturan berikut:

### 1. Validasi Berdasarkan Transaksi & Logistik Cepat

- Kode voucher dianggap "terpakai" segera setelah pembeli baru menyelesaikan transaksi pembayaran di website (bukan saat barang sampai)
- Karena pengiriman di satu pulau sangat cepat (1 hari), ini aman bagi batas waktu pengguna
- Penggunaan voucher referral hanya dihitung sah oleh sistem jika akun baru tersebut melakukan registrasi DAN aktivasi QR Code fisik yang valid dalam kurun waktu tertentu setelah barang diterima

### 2. Pencegahan Aktivasi Palsu (Fake Activation Loop)

**Pagar Perangkat & IP:** Sistem membatasi agar 1 perangkat fisik (Device ID/Fingerprint) dan 1 alamat IP hanya bisa mendaftarkan/mengaktivasi maksimal 2 akun/QR Code baru untuk menghindari skema patungan manipulatif.

**Verifikasi WhatsApp:** Setiap akun baru wajib melewati verifikasi OTP via nomor WhatsApp yang aktif untuk mencegah pendaftaran menggunakan puluhan email palsu.

### 3. Batas Anggaran (Budget Cap)

- Kuota klaim saldo e-wallet dibatasi mingguan/bulanan (contoh: 20 orang pertama setiap minggu) untuk mengamankan arus kas operasional dari lonjakan viral tak terduga
- Pembatasan wilayah pengiriman (Checkout Geofencing) di dalam aplikasi sehingga transaksi hanya diproses untuk alamat di satu pulau target peluncuran

## 📲 Sistem Klaim & Penerapan di Aplikasi

Agar proses klaim hadiah berjalan otomatis, transparan, dan aman, berikut adalah rancangan alur serta integrasi teknis di dalam aplikasi Balikin:

### 1. Alur Pengguna (User Journey)

- **Pemberitahuan Otomatis:** Saat penggunaan voucher mencapai target 10/10, sistem mengirim notifikasi (WhatsApp/Email) berisi instruksi klaim
- **Dashboard Referral Aktif:** Tombol klaim di profil pengguna yang sebelumnya tidak aktif (disabled) kini berubah menjadi aktif dan berwarna hijau mencolok dengan efek animasi halus (pulse)
- **Modal Input Data:** Pengguna menekan tombol, memilih jenis e-wallet pilihan (GoPay, OVO, DANA, ShopeePay), lalu memasukkan nomor telepon tujuan transfer
- **Pembaruan Status:** Setelah data dikirim, tombol klaim berubah status menjadi "Sedang Diproses" sementara admin memvalidasi transaksi

### 2. Arsitektur Database (Skema Drizzle ORM)

Tabel `referral_vouchers` diperluas dengan kolom kontrol klaim untuk menjaga konsistensi status transaksi:

```typescriptTabel referral_vouchers diperluas dengan kolom kontrol klaim untuk menjaga konsistensi status transaksi:import { pgTable, uuid, varchar, integer, timestamp, boolean } from 'drizzle-orm/pg-core';
import { users } from './users'; 

export const referralVouchers = pgTable('referral_vouchers', {
  id: uuid('id').primaryKey().defaultRandom(),
  userId: uuid('user_id').references(() => users.id).notNull(),
  code: varchar('code', { length: 50 }).notNull().unique(),
  usageCount: integer('usage_count').default(0).notNull(),
  maxUsageTarget: integer('max_usage_target').default(10).notNull(),
  
  // Kontrol Klaim Reward
  claimStatus: varchar('claim_status', { length: 20 }).default('NOT_ELIGIBLE').notNull(), 
  // Opsi Status: 'NOT_ELIGIBLE', 'READY_TO_CLAIM', 'PENDING_PROCESSING', 'SUCCESS'
  walletProvider: varchar('wallet_provider', { length: 20 }), // GOPAY, OVO, DANA
  walletNumber: varchar('wallet_number', { length: 20 }),
  claimedAt: timestamp('claimed_at'),
  
  createdAt: timestamp('created_at').defaultNow().notNull(),
  expiresAt: timestamp('expires_at').notNull(),
});
```

### 3. Logika Backend (Server Action - Next.js)

Fungsi validasi di bawah ini menangani logika permohonan klaim agar tidak terjadi double-claim (klaim ganda) atau manipulasi data:

```typescript
// app/actions/claim-reward.ts
'use server'

import { db } from '@/db';
import { referralVouchers } from '@/db/schema';
import { eq, and } from 'drizzle-orm';
import { auth } from '@/auth'; 

export async function claimEWalletReward(voucherId: string, provider: string, walletNumber: string) {
  const session = await auth();
  if (!session?.user) return { success: false, error: 'Akses tidak diizinkan.' };

  // 1. Verifikasi kepemilikan voucher dan pencapaian target 10 orang
  const [voucher] = await db
    .select()
    .from(referralVouchers)
    .where(
      and(
        eq(referralVouchers.id, voucherId),
        eq(referralVouchers.userId, session.user.id)
      )
    );

  if (!voucher || voucher.usageCount < voucher.maxUsageTarget) {
    return { success: false, error: 'Target 10 kali penggunaan belum terpenuhi.' };
  }

  if (voucher.claimStatus !== 'READY_TO_CLAIM') {
    return { success: false, error: 'Hadiah sudah pernah diklaim atau sedang diproses.' };
  }

  // 2. Kunci transaksi ke status peninjauan admin (PENDING)
  await db
    .update(referralVouchers)
    .set({
      claimStatus: 'PENDING_PROCESSING',
      walletProvider: provider,
      walletNumber: walletNumber,
      claimedAt: new Date(),
    })
    .where(eq(referralVouchers.id, voucherId));

  return { success: true, message: 'Permintaan klaim berhasil dikirim! Saldo akan masuk maks 1x24 jam.' };
}
```

### 4. Visualisasi Komponen Antarmuka (UI/UX App)

Tampilan pada halaman dashboard referral pengguna menggunakan elemen interaktif:

**Indikator Kemajuan (Progress Bar):** Visualisasi Progress dari Shadcn UI untuk menampilkan persentase target secara dinamis (contoh: 4/10 Teman Bergabung).

**Kondisi Tombol:**
- **Belum Layak (< 10):** Tombol non-aktif berlabel "Ajak [Sisa] Teman Lagi untuk Klaim"
- **Layak (= 10):** Tombol menyala hijau terang (`bg-green-600 animate-pulse`) bertuliskan "Ambil Rp50.000 Sekarang!"
- **Sedang Ditinjau:** Tombol berubah menjadi status non-aktif berlabel "Sedang Dikirim (Maks 24 Jam)"
- **Selesai:** Tampilan lencana (Badge) bertuliskan "Terkirim ✓"

### 5. Panel Pengendali Admin (Admin Dashboard Panel)

Di sisi backend admin Balikin, terdapat satu tabel antrean khusus untuk memproses pengiriman saldo secara manual ataupun otomatis:

- **Daftar Antrean:** Menampilkan baris data dengan status PENDING_PROCESSING lengkap dengan Nama Mahasiswa, Kampus, Nomor E-Wallet, dan Nominal
- **Tombol Eksekusi:** Begitu Anda melakukan transfer, tombol "Konfirmasi Selesai Transfer" ditekan, yang secara otomatis:
  - Mengubah status di database menjadi SUCCESS
  - Memicu notifikasi penyelesaian via WhatsApp/Email kepada pengguna
