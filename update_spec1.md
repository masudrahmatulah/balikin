Update Spesifikasi: Strategi Pemasaran & Arsitektur Admin Dashboard (Balikin)1. Model Bisnis & Produk BaruSistem harus mendukung empat pilar distribusi fisik ke digital:Mass-Retail (Bulk QR): Produksi massal gantungan kunci/tag dengan status unclaimed. Dijual secara retail, pembeli melakukan klaim setelah pembelian.B2B & Bundling (Niche Markets): Paket khusus (seperti Student Kit) untuk instansi/sekolah dengan branding khusus dan dashboard pemantauan distribusi bagi mitra.Direct-to-Consumer (D2C Custom): Pesanan kustom via website (bentuk, warna, desain). Barang diproduksi on-demand dan dikirim dalam status active (tanpa perlu klaim).Sticker Bundles: Paket stiker (isi 5, 10, 15, 20) yang bisa ditempel mandiri oleh user pada barang apa saja. Menggunakan alur scan-to-claim.2. Logika Keamanan & Aktivasi (Claim Logic)Untuk produk non-custom (Bulk & Stiker), sistem harus mencegah aktivasi ilegal sebelum pembelian.Dual-Validation Claim: - Public ID (Serial Number): Tertera di QR Code untuk identifikasi publik.Secret Token (Claim Code): Kode rahasia (3-4 digit) yang tersembunyi di balik lapisan gosok (scratch-off) atau di dalam kemasan.Status Tag:unclaimed: Sudah dicetak, belum ada pemilik.in_transit: (Khusus Custom) Sedang dikirim, sudah terikat ke user.active: Sudah diklaim dan profil aktif.3. Arsitektur Admin DashboardDashboard dibagi menjadi modul fungsional untuk efisiensi operasional:A. Module: Production & Batch ManagerBatch Generation: Generate UUID/Serial Number massal berdasarkan kategori produk.VDP Export (Variable Data Printing): Fitur ekspor data QR ke format PDF/CSV siap cetak (otomasi tata letak).Inventory Tracking: Mengelola status fisik tag dari gudang hingga ke tangan retailer/mitra.B. Module: Custom Order & FulfillmentOrder Queue: Antrean pesanan kustom yang sudah dibayar.Production Specs: Menampilkan detail kustomisasi user (Warna QR, Bentuk Akrilik).Shipping Integration: Input resi pengiriman yang memicu aktivasi otomatis tag.C. Module: B2B/Partner PortalDistribution Analytics: Mitra (Sekolah/Perusahaan) dapat melihat statistik berapa banyak tag yang sudah diklaim oleh anggota mereka.White-label UI: Pengaturan branding dinamis (Logo/Warna) pada profil barang yang hilang dalam batch tertentu.D. Module: Customer SuccessVerification Center: Review pengajuan identitas user untuk badge "Verified".Manual Override: Fitur untuk membantu user melakukan klaim manual atau reset token jika terjadi masalah fisik pada produk.4. Pembaruan Skema Database (Supabase)Table batches: id, name, type, created_at, partner_id (optional).Table tags (Updates):batch_id: Foreign key ke tabel batches.status: enum (unclaimed, in_transit, active, lost).claim_token: Hashed secret code untuk validasi aktivasi.production_meta: JSON untuk menyimpan detail kustomisasi (warna, bentuk).5. Prinsip UI/UX AdminEfficiency-First: Dukungan untuk barcode scanner fisik guna mencari data tag secara instan.Mass Action: Fitur pemilihan banyak item (bulk select) untuk mengubah status produksi atau pengiriman.Color Coding: Indikator warna status tag (Abu-abu: Unclaimed, Biru: Proses, Hijau: Aktif, Merah: Hilang).6. Alur Kerja (Workflow)Alur Bulk: Generate -> Print -> Distribute -> User Scans -> Input Claim Code -> Active.Alur Custom: Order -> Paid -> Production Queue -> QC -> Ship (Input Resi) -> Auto-Active.
